# Состояние работ и открытые вопросы

## Что сделано

### Этап 1 — ядро
- `Organization` + `OrganizationDomain`, разрешение арендатора по домену.
- `TenantModel` / `TenantManager` с автоматической фильтрацией и безопасным
  поведением при неопределённой организации.
- Кастомный `User` (вход по email или телефону) — в первой миграции.
- Роли через `Membership`: `platform_admin`, `owner`, `admin`, `teacher`,
  `parent`, `student`. У пользователя может быть несколько ролей и организаций.
- Объектные права в `apps/journal/access.py`.
- Второй фактор (TOTP) для владельца, администратора и админа платформы,
  резервные коды, `django-axes`, истечение сессии по неактивности.
- Шифрование полей с ПДн, мягкое удаление, `AuditLog`, `Consent`,
  автоудаление по истечении срока хранения.

### Этап 2 — публичный сайт
- Первый экран по утверждённому макету 1a: токены, шрифты, шкала на 20
  сегментов, тема с сохранением выбора и без вспышки.
- 12 блоков лендинга в порядке из спецификации, страница профориентации,
  «спасибо», три правовые страницы.
- Форма заявки: отдельный чекбокс согласия, honeypot, проверка времени
  заполнения, лимит по IP, маска телефона, состояния idle/submitting/error.
- Учёт UTM, referrer, page_path, версии политики; фиксация согласия.
- `sitemap.xml`, `robots.txt`, Schema.org, Open Graph, cookie-баннер,
  реквизиты ИП в подвале.
- Уведомление в Telegram через Celery с ретраями; сбой отправки не ломает
  ответ пользователю.

### Этап 3 — журнал
- Справочники: учебный год, предметы (34 часа), модули 2026/27 фикстурой,
  группы, ученики, родители, педагоги.
- Оценивание: `GradeItem`, `Grade`, `ModuleResult`, `GradingScale`,
  структура 100 баллов, валидация лимита, блокировка выставления задним
  числом, пересчёт под блокировкой строки.
- Кабинет педагога: занятия на сегодня, журнал занятия с автосохранением
  и устойчивостью к обрыву сети, планирование модуля со счётчиком остатка,
  тематическое планирование.
- Кабинет родителя: карточка ребёнка, баллы с уровнями, динамика,
  расписание недели, комментарии, оплаты, переключатель между детьми.
- Кабинет ученика: отдельный вход, свои баллы и разрывы до порогов, цели,
  индикатор состояния, домашние задания, расписание.
- Кабинет администратора и владельца: воронка заявок с обязательной
  причиной отказа, ученики с восстановлением удалённых, ФОТ, дашборд.

### Этапы 4–5 — базовый объём
- Цели: академические, личные (открытые и скрытые), цели-результаты.
- Индикатор состояния: отметка за сегодня и за вчера, без штрафов
  за пропуск, агрегат наружу не выводится.
- Экспорт xlsx: успеваемость по модулю, ученики, ФОТ, цели.
- Оплаты: модель, интерфейс `PaymentProvider`, ручная отметка.

## Что осталось

| Задача | Почему не сделано |
|---|---|
| Эквайринг | На старте оплата по реквизитам, интерфейс заложен |
| Фото педагогов и помещения | Нет файлов оригиналов: конвейер обработки готов, стоят брендовые заглушки |
| Перенос текстов с tznakso24.ru | Сайт недоступен из среды разработки — нужен доступ или выгрузка текстов |
| Тексты правовых документов | Нужна вычитка юристом, стоит рабочий шаблон |
| Уведомление Роскомнадзора | Организационный вопрос, не технический |
| Дорожная карта как визуальный маршрут | Есть данные и цели, визуализация — после журнала в бою |
| Проверка на реальном телефоне | Требует физического устройства, эмулятор не считается |
| Восстановление бэкапа на чистой машине | Делается при первом деплое, форма отчёта в docs/DEPLOY.md |

## Отклонения от ТЗ

Все — осознанные, обоснование в `docs/ARCHITECTURE.md`.

| Что в ТЗ | Что сделано | Почему |
|---|---|---|
| Tailwind CSS | Один файл CSS с токенами макета | Дизайн токен-ориентированный, а не утилитарный; нет шага сборки на сервере |
| Alpine.js | Обычный JS, ~150 строк | Интерактива мало, бюджет первого экрана важнее |
| Manrope из Google Fonts | Self-hosted сабсет | Меньше запросов и не передаём IP посетителя третьей стороне |
| `django-cryptography` | Своё поле на `cryptography.fernet` | Библиотека не поддерживает Django 5 |
| `django-celery-beat` | Расписание в коде Celery | Одна задача в сутки, лишняя таблица не нужна |
| «Полностью асинхронный» | HTMX + Celery, sync-воркеры | Раздел 2.2 самого ТЗ; обоснование в ARCHITECTURE.md §1 |
